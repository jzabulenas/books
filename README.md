# MusicDiscover

An AI-powered music artist discovery app. Tell it artists you already like, and it suggests new ones you probably haven't heard of - each with a genre and a one-line reason why you might like it.

## Overview

The core loop is simple: add artists you like, generate recommendations, and curate them. Recommendations are generated by an LLM (OpenAI, via Spring AI) based on your liked-artist list, automatically excluding anything you've already saved, blocked, or removed from Saved. Save the suggestions worth exploring, and block the ones you never want to see again.

## Features

- **Passwordless login** - sign in via a magic link emailed to you, no password required
- **Liked artists** - build a list of artists you already enjoy, which drives the recommendation engine
- **AI-generated recommendations** - generate 5 new artist suggestions at a time (name, genre, and a reason), once you've liked at least 3 artists
- **Save for later** - bookmark recommendations you want to revisit; removing one from Saved dismisses it so it's never suggested again
- **Block artists** - mark a suggestion as "don't suggest again" so it's excluded from future recommendations

## Tech stack

**Backend** - `backend/`

- Java 21, Spring Boot 4.1 / Spring Framework 7
- Spring Security 7 (passwordless magic-link / one-time-token login)
- Spring Data JPA + Flyway migrations, on MariaDB
- Spring AI (OpenAI `gpt-4o-mini`) for generating recommendations
- Spring Mail (magic-link emails), Spring Session (JDBC-backed sessions)
- Tests: REST Assured (e2e)
- Built with Maven

**Frontend** - `frontend/`

- Angular 21 (standalone components, signals-based state)
- Angular Material + CDK
- Tests: Playwright (e2e)

## Prerequisites

- JDK 21
- Node.js (LTS) and npm
- Docker (to run MariaDB and Mailpit locally)
- An OpenAI API key (for generating recommendations)

## Configuration

The backend is configured entirely via environment variables (see `backend/src/main/resources/application.yaml`):

| Variable                          | Required | Default                   | Purpose                                          |
| --------------------------------- | -------- | ------------------------- | ------------------------------------------------ |
| `SPRING_AI_OPENAI_API_KEY`        | Yes      | -                         | OpenAI API key used to generate recommendations  |
| `MARIADB_USERNAME`                | Yes      | -                         | Database username                                |
| `MARIADB_PASSWORD`                | Yes      | -                         | Database password                                |
| `MAIL_HOST`                       | No       | `localhost`               | SMTP host for sending magic-link emails          |
| `MAIL_PORT`                       | No       | `1025`                    | SMTP port                                        |
| `MAIL_USERNAME` / `MAIL_PASSWORD` | No       | _(empty)_                 | SMTP credentials                                 |
| `MAIL_AUTH`                       | No       | `false`                   | Whether SMTP requires auth                       |
| `MAIL_STARTTLS`                   | No       | `false`                   | Whether to use STARTTLS                          |
| `MAIL_FROM`                       | No       | `noreply@music-rec.local` | From-address for magic-link emails               |
| `APP_BASE_URL`                    | No       | `http://localhost:4200`   | Frontend base URL, used to build magic-link URLs |
| `APP_BACKEND_URL`                 | No       | `http://localhost:8080`   | Backend's own public URL                         |
| `CORS_ALLOWED_ORIGINS`            | No       | `http://localhost:4200`   | Allowed CORS origin(s)                           |

By default the backend connects to `jdbc:mariadb://localhost:3306/music`. For local development without Docker, either point a local MariaDB instance at that database or use [Mailpit](https://github.com/axllent/mailpit) to catch magic-link emails when `MAIL_HOST`/`MAIL_PORT` aren't overridden - see [Running locally](#running-locally) for the Docker-based option.

## Running locally

The easiest way to get a database and a mail catcher running is via the provided Docker Compose file, which also builds and runs the backend itself:

```bash
SPRING_AI_OPENAI_API_KEY=sk-... docker compose -f docker-compose.e2e.yml up -d
```

This starts:

- MariaDB (database `music`, user/password `music`/`music`)
- [Mailpit](https://github.com/axllent/mailpit) (SMTP catcher, web UI at `http://localhost:8026`) - view magic-link emails here
- the backend, on `http://localhost:8081`

Then run the frontend against it:

```bash
cd frontend
npm install
npm run start:e2e   # ng serve on port 4201, proxied to the backend on 8081
```

Open `http://localhost:4201` and sign in with your email - check Mailpit for the magic link.

Alternatively, to run the backend directly (e.g. with your own MariaDB instance) instead of via Docker:

```bash
cd backend
MARIADB_USERNAME=music MARIADB_PASSWORD=music SPRING_AI_OPENAI_API_KEY=sk-... ./mvnw spring-boot:run
```

```bash
cd frontend
npm install
npm start   # ng serve on port 4200, expects the backend on 8080
```

Open `http://localhost:4200`.

## Testing

**Backend** (from `backend/`):

```bash
./mvnw test -Pe2e     # e2e tests (requires the Docker Compose stack running)
```

**Frontend** (from `frontend/`):

```bash
npm run e2e           # e2e tests (Playwright; requires the Docker Compose stack running)
npm run e2e:ui         # e2e tests with the Playwright UI
```
